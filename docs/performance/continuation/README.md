## Interpretation and reproduction

Phase drivers alternate before/after order by case, never run measured renders alongside builds/tests/profilers, and preserve identical quality inside each pair. Ordinary cold/warm public calls, isolated uninstrumented native calls, separate instrumented phase runs, sustained loops with cleanup, and fresh one-render RSS are distinct regimes. Cold excludes fixture construction and R startup; operating-system file caches are uncontrolled. Rprofmem covers R allocations, not all C++ allocation. Native payload counters are not total RSS. Three samples give descriptive median/p95, not a stable tail estimate. Every regression stays in the tables.

New default helpers retain the old R output route under `RAYVERTEX_REFERENCE_OUTPUT=1`; `RAYVERTEX_REFERENCE_VARYINGS=1` retains common attribute storage independently of the output buffer/debug contract. Existing scalar coverage/tree transparency/reference scheduling/full-buffer switches remain. `RAYVERTEX_PARALLEL_BINS=1`, `RAYVERTEX_MACROTILE_EDGE=16|32|64`, and `RAYVERTEX_BLOCK_COVERAGE=1` enable experiments independently. Binning histograms have a 32 MiB limit and fall back to serial below two useful chunks. Macro edges round up to whole existing microblocks. These are developer environment switches, not new public quality presets.

The measured bin and macrotile phases include list/histogram allocation and construction, not just the worker loop. Worker counts honor serial operation and the existing pool. Macrotile scheduling scratch/task counters and bin histogram/worker counters are recorded alongside stage timings. No hardware-counter or false-sharing improvement is claimed. The block-extrema phase retains logical candidate counts even when it skips rejected blocks; its extra edge-sample counters identify skipped work.

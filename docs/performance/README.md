# CPU rasterizer implementation and measurements

The first structural continuation implements exact sparse transparency, once-per-primitive setup and contiguous bins, homogeneous clipping and depth corrections, demand-driven buffers, parallel screen work, conservative opt-in visibility, exact shadow/light specialization, shared environment variants, and explicit prepared scenes. Native profiling led to stable geometry views; expanded measurements led to composing the invariant SSAO projection once per frame. Existing rendering quality settings and ordinary R scene-list calls are preserved. Visibility and indexed transforms remain experimental and disabled by default.

## Measurements and reproducibility

Hardware: Apple M1 Max, 10 physical/logical cores (8 performance and 2 efficiency), 64 GiB RAM; macOS 15.7.3; native arm64 R 4.6.0; Apple clang 16.0.0. Release flags remain `-falign-functions=64 -Wall -g -O2`, without fast-math or a native-ISA requirement. A temporary Makevars bypasses the unavailable compiler cache; the package gains no C++ standard requirement or thread runtime.

Each structural phase report contains before/after cold and warm public-call timings, isolated native medians/p95, separately instrumented stage timings/counters, R allocations, fresh-render peak RSS, sustained loops including output cleanup, and per-buffer differences. Three warm/native samples and five-frame sustained loops are used for the phase comparisons; p95 is descriptive, not a stable tail estimate. Short-scene, allocator and GC variation is retained. Runs are sequential, with no competing renderer, compilation, tests or profiler during measurements.

Cold means the first public render after loading R/package and constructing the fixture. It includes scene preparation, decode, rendering and R postprocessing; it excludes interpreter startup and fixture creation. It is not disk-cache cold. Prepared-scene reports separately include preparation, first-render and preparation-plus-first costs; isolated native calls are not substituted for prepared-scene throughput. Fresh RSS includes R, fixture construction and one render. Diagnostic-process RSS also includes retained outputs and instrumentation. Rprofmem excludes C++ allocations; native payload counters do not measure every allocation.

The [prepared-scene report](structural/prepared/results.md) documents measured reuse and amortization limits. `prepare_scene(scene)` snapshots merged geometry, deduplicated materials and decoded material textures. `update_prepared_scene(handle, scene)` returns a replacement snapshot. Original-list/file changes do not affect existing handles. Camera, lights, effects, callbacks, shadows and environment preparation are per-frame; there is no shadow cache or persistent pool. Handles reject serialization/fork reuse and release assets through native finalization.

## Current implementation boundaries

This does not implement every proposed experiment. Bins default to deterministic serial count/prefix/fill, with bounded parallel construction available experimentally. Spatial macrotiles are optional. Normal transforms are not cached and object/submesh bounds remain absent. Native geometry views use the existing column-major arrays, without a persistent fully packed prepared geometry copy. Image, outline and tile layouts retain explicit existing conversions rather than adopting a universal new layout.

The visibility experiment proves opacity only for a conservative subset of untextured shaders. Unknown/mixed tiles fall back. It has no depth-prepass comparison or near-first reordering. Whole-block coverage extrema are optional; hierarchical depth, ISA-specific SIMD and mixed precision remain unimplemented. No numerical tangent-inversion replacement or changed tangent coordinate convention is enabled. Coincident point-light directions retain their legacy exceptional normalization behavior; changing that convention needs a separate correctness phase. Plotting/encoding, disk-cache cold, hardware counters, Windows/Linux and actual Emscripten execution are not measured.

Phase diagnostics still combine material decode with shader construction and default forward coverage with shading; R postprocessing boundaries are coarse, and no shadow-tap counter or total native allocation tracer is supplied. Visibility instrumentation separates summed tile-worker coverage/shading time, which is not multiworker wall time.

The finite release corpus cannot prove every extreme-coordinate, degenerate UV, allocation-failure, or interrupt path. The upstream resize alignment UBSan report reproduced on the final build and remains an explicit validation failure; macOS LeakSanitizer is unavailable. See the [structural validation report](structural/validation.md) for the final tests actually run and their outcomes.

## Developer reproduction

Use isolated libraries for each revision and the scripts under `tools/`; all drivers assert the loaded library path. Start with [current validation commands](structural/validation.md), then use `bench-rasterizer-structural.py` for phase comparisons and `bench-rasterizer-structural-matrix.py` for worker/quality/visibility sweeps. The latter compares then removes its own large temporary image files while retaining every difference metric; golden references stay committed. The original [validation commands](validation-commands.md) document the earlier, pre-clipping implementation.

Developer-only environment switches select tree transparency (`RAYVERTEX_REFERENCE_TRANSPARENCY`), full buffers (`RAYVERTEX_REFERENCE_BUFFERS`), serial screen passes (`RAYVERTEX_REFERENCE_SCREEN`), original scheduling (`RAYVERTEX_REFERENCE_SCHEDULER`) and uncached material decodes (`RAYVERTEX_REFERENCE_ASSETS`). `RAYVERTEX_INDEXED_TRANSFORMS` and `RAYVERTEX_VISIBILITY` are opt-in experiments. `RAYVERTEX_BATCH_BLOCKS` defaults to 64. Clear these controls for normal timings. `RAYVERTEX_PARALLEL_BINS=1`, `RAYVERTEX_MACROTILE_EDGE=16|32|64`, and `RAYVERTEX_BLOCK_COVERAGE=1` enable the new opt-in experiments. `RAYVERTEX_REFERENCE_OUTPUT=1` restores R output helpers and `RAYVERTEX_REFERENCE_VARYINGS=1` restores common attribute storage for direct comparisons. `RAYVERTEX_PROFILE` writes diagnostics after worker barriers; it is off by default.
